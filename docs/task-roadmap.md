# 当前任务总计划 · 2026-11-09

> 用户最新确认：人负责寻找目标和大幅转向，程序只对中心附近的已选可靠目标做有限二维微调，人工主动转向时让步。当前实现与验收顺序以 [人主导微调交接](human-led-assist-handoff.md) 为准；下方历史自主闭环结果仅是诊断证据，不是产品要求。人主导契约、HA05 审计和 HA06 对照已经接到仿真。区域、死区、步长和恢复等待仍是实验值。Linux 上已用 ONNX Runtime 跑通 YOLO11n 闭环。TensorRT 需要 NVIDIA GPU，本机没有，结果保持 UNKNOWN。ReID、person 95% 和远程 CI 继续后置。

## 当前所处位置

主要工程基础和首个端到端链路已具备。第 7 阶段的当前产品回路是：已选可靠目标进入中心附近后，按实验限幅把该目标往画面中心送。人的大转向仍优先。证据和命令见 [HA06 实验](ha06-experiments.md) 与 [HA07 复审材料](ha07-batch-review.md)。不能把这次仿真通过等同 TensorRT 实跑或整个平台完成。

## 后续推进顺序

1. 根据已有录像诊断 head 漏匹配、背景误检、镜头补偿拒绝及断轨；无需立即重做整批标注。
2. 坐标/时钟/命令接口、增量仿真执行器、PID、变化延迟及渲染→YOLO→执行→新图像工程回路已实现，证据见 sim-incremental.md、sim-image-loop.md。人主导区内微调的同源开/关、像素闭环、双人和延迟故障见 ha06-experiments.md。继续完成 Windows TensorRT `human_led` 实跑、真实异步调度、控制标定和最终精度验收；现有 FAILED/UNKNOWN 必须保留。
3. 在可靠身份真值和遮挡问题证据支持下推进 ReID 实验，保持独立开关及退化检查。
4. 按用户后置安排补足数据并优化检测训练，验证 person 95% 等目标；不把当前诊断窗口用于训练后再拿同一批宣称测试提升。
5. 做最终代表性测试、长时运行、远程 CI 与交付整理；必要时根据证据返回前面阶段修复。

每阶段先定义输入、输出、时钟/坐标和验收，再实现，使用同源数据做对照；记录负结果，不为了过门槛临时放宽阈值。head/person 类别固定 0=head、1=person；现有 group_id 是局部轨迹编号，不是类别编号，也不能直接当作跨遮挡/场景的永久人物身份。
