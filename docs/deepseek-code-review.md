# DeepSeek 新增代码评审 · 2026-11-07

评审 HEAD 7ff9f14，重点为 TRACK-02、SIM-01、MOT-08。本轮仅审查，代码保持原状。CPU CTest 21/21、pytest 10/10 在本机通过；现有测试通过不能覆盖以下缺陷。

## P1 · 消融使用不同时间窗口，缺失轨迹被排除，结论可能反转

src/sim/simulator.cpp 336–338 仅在 selected 存在时累计误差，352–358 达到成功即提前 break。不同算法建立轨迹和成功的时刻不同，导致 MAE 的分母和区间不同。它计算的是执行器到当前真值的距离，尚未提供预测到查询时刻的真值误差，无法单独衡量 IMM。

实测 artifacts/sim/sim-02-base/runs.jsonl 与 sim-02-byte/runs.jsonl 的 low_conf：base 12 个有效样本，截止帧 12，MAE 68.7321；byte 11 个样本，截止帧 16，MAE 65.4415。两者共同帧 6–12 的执行器误差分别是 11.5257 与 100.7153 px。现有“改善约 3.3 px”不能支持算法收益结论。

建议固定完整回放窗口，成功/失败事件另记，不截断算法评估；报告无轨迹覆盖率以及估计误差、未来预测误差、控制误差，所有方法使用相同输入和时间窗。

## P1 · 仿真用真值选择控制对象

src/sim/simulator.cpp 231–243 每帧将与 truth_x/truth_y 最近的非 Tentative 轨迹直接交给控制器。出现误检、轨迹碎裂、重新编号时，控制器利用运行系统拿不到的真值自动选回对象。真实选择管理器会保留暂失 ID 或报告不可用，两者行为不同。选错对象的代价因此被隐去。

建议首次显式指定关注对象，此后通过 mot::Selection 更新；真值仅供独立评分模块使用。添加假目标更靠近预测位置、旧 ID 丢失和重新出生的验收。

## P1 · ByteTrack 分支丢失身份歧义门控

src/tracking/tracker.cpp 158–161 只把 Observation.ambiguous 复制给轨迹，缺少原分支对行/列近似关联代价的检查。高/低两阶段都走这个 apply。两人交叉时可以输出低歧义 Confirmed，从而允许 Selection 接受实际不可区分的对象。

本机复现位于 artifacts/code-review/ambiguous.cpp：两个高置信人物先在 x=100/102 出现并确认，第三帧均在 x=101；默认分支两轨迹 ambiguous=1，byte_track=1 两轨迹 ambiguous=0。通过直接编译当前 tracker.cpp 复现。

建议共享关联更新和歧义计算，在两阶段中都标记同等代价候选；回归覆盖近重合、完全重合和低分恢复。

## P2 · 成功阈值按屏幕归一化，与目标尺寸无关

src/sim/simulator.cpp 302–304 用画面 width/height；总设计 10.2 要求按目标 w/h。默认 640 宽画面上，水平 10 px 的误差归一化为 0.015625，可通过 0.02 阈值；对宽 12 px 的小目标，应为 0.8333，甚至已经偏出目标。pixel_epsilon 和 overshoot 也采用画面对角线，大小目标比较失去意义。

建议用当前可见目标尺寸归一化，先明确中心误差定义，再重新跑所有场景；加 12×24 小目标、10 px 偏移的拒绝验收。

## P2 · 实时节奏等待无法被关闭唤醒

apps/trt_infer/replay.cpp 230–232 直接 sleep_until。consumer 失败只 queue.close，而主线程先 join producer。出现较大的媒体 PTS 间隔或极低帧率时，即使写入/推理已经失败，仍等待到下个媒体时刻才退出，关闭队列无法解除休眠。队列单元测试只覆盖 condition_variable，不覆盖这条实际生产路径。

建议使用可被取消信号唤醒的定时等待，消费者异常时同时发出取消；针对两帧间隔很长且首帧消费失败的回放验证有界退出时间。

## 下一步判断

IMM 开关应在以上评估与身份门控问题修复后实施。先建立固定事件窗口、同输入、同真值、固定查询时域的 CV 基线，再加入 IMM 做急停/变向消融。镜头补偿与 ReID 可以继续后置。实景身份真值、负样本、95% 检测召回和远程 CI 仍需单独验收。
