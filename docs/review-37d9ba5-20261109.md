## P1：异步人工接管的停止请求未进入执行事件队列

位置：src/sim/simulator.cpp:825–827，withdraw_assist 设置 stop_request_ready，却没有像其他停止请求路径那样 enqueue(Stage::Execution, stop_request_ready, ..., 0)。异步模式仅在 Execution 事件处理时调用 applyDueCommands；人工接管后不再生成命令，也就可能再没有执行事件来消费这个停止请求。

独立成对反例：目标在中心右侧 20px、incremental_control/view_feedback/encoder_compensation 开启，feedback_transport=1、feedback_timeout_ms=5000、stop_request_delay_ms=20；0.28s 输入 takeover=true 并保持。两份配置只改变 async_stages。

| 观察 | 固定步长 async0 | 异步 async1 |
|---|---|---|
| 接管后取消请求日志 | 有 | 有 |
| 设备 cancelled 事件 | 0.300s | 没有 |
| 窗口结束仍记 active | 无 | 2.360s 的 window_end_active |
| 最终 camera_x | 1px | 0px |

这里不是异步模式“停止更快”：该模式未按停止时刻推进物理执行/终止，造成残余位移和停止状态证据不可信。0.300s 的请求应有实际消费及终结证据，不能只把 assist_cancel=true 当作设备已经停止。此前坐标一致性探针通过仅证明样本和相机快照相互一致，不能覆盖物理推进。

修复要求：将辅助停止请求加入同一执行调度契约，停止优先于同刻普通命令；明确队列拒绝的失败处理；即使停止后不再发任何新命令，也须按时处理停止和已接受命令的执行/到期。补固定/异步成对测试，核对请求、执行、确认、残余位移与窗口末状态。不能仅修改最终日志或等下一条普通命令顺便处理。

证据：artifacts/review-37d9ba5-probes/stop.py、stop-results.json、stop-v2-async0/、stop-v2-async1/。初版夹具未设置停止所需 feedback_transport，被配置校验正确拒绝；结论来自合法的 v2 输入，两场景均执行完成。
