## 目标与范围

人寻找目标并负责大幅转向；程序只对中心区域内已选可靠目标进行有限二维微调。人工接管优先，区外、身份歧义、过期观测、断连时停止产生辅助命令。先在自建仿真/测试窗口验证，再接已确认的串口设备。不加入点击、击发、自动寻找目标或自动切换人物。不是训练镜头控制策略。

Grok 实现并提交分批证据，Codex 独立复审。本文是新增实施基线，不表示功能已完成。旧问题与旧失败证据保留。参数自动调整属于后续实验，本轮先完成按实际 dt 更新的固定参数 PID 对照。

## 接口、坐标和时间

建议新增 include/vision/control/、include/vision/io/、src/control/、src/io/，具体文件布局可按仓库调整。控制器单一线程或事件循环拥有积分、微分、状态和命令序号；串口写入也由单一所有者串行处理，推理线程不阻塞等待设备。

- Observation：frame_id、capture_ns、publish_ns、control_image_size、ROI/letterbox 变换、track_id、目标点来源/像素位置、置信度、当前预测协方差。
- Intent：run_id、epoch、command_id、frame_id、track_id、generated_ns、deadline_ns、目标中心误差(px)、dx/dy(device counts)、控制器版本。
- TransportEvent：queued/write_started/write_completed/ack_received/cancel_requested/local_cancelled/expired/failed/disconnected；携带命令与时钟关联、字节数、错误码、raw response。设备未返回命令序号时 command_id 匹配标记 inferred，而非 verified。
- ExecutionObservation：来源 device_verified 或 vision_estimated，观测时间、位移、误差、置信度。没有执行证据时 applied_ns=null，禁止用 WriteFile 返回时间补填。

本机延迟统一 steady_clock 纳秒；媒体 PTS、设备时间、GPU event 分别记录，不直接相减。设备时钟有校准映射才计算跨设备耗时。命令过期和停止按实际事件时间执行，异步模式无后续普通命令也必须消费停止/到期事件。

模型320、原采集画面、控制ROI和设备counts是不同坐标。像素到设备单位用明确的标定变换与单位；目标点可为关联头部实测点或框内身体归一化点，来源记录，不能套旧“头在person框外”的公式。

## 串口协议与恢复

已读旧主机代码：move 序列化为 ASCII `M dx dy\n`；8N1；代码注释称固件每命令返回 OK。必须继续检查实际固件及设备版本，不能从注释推定 OK=移动完成。点击/击发协议不迁移。

部分 WriteFile 成功不等于完整命令成功：记录实际字节数，有限重试剩余字节，超时后不得无条件重发整个相对位移包。半包/失联进入 fault，按协议重新同步，禁止把残留前缀拼到下一条命令。无序号的旧协议最多保留一个待应答命令，ACK匹配不确定时进入未知/停止，不把迟到 OK 归给新 epoch。

有界发送队列，待发辅助只保留最新完整意图，淘汰尚未写出的旧意图并记原因；已写出的不能谎称撤回。人工接管立即阻止新辅助，撤销可撤销队列；若固件支持 STOP，发送优先停止并等待有时限确认；若无 STOP，报告“不支持”，只依靠限步长/有限在途数限制残余，不伪造停止应答。不假设 M 0 0 可以取消已排队移动。

断连、端口占用、读写超时、设备重启、队列满、磁盘满均有明确 fault 状态；重连不自动恢复辅助，须新的 epoch 和显式重新启用。若人工输入不可区分设备注入，先提供明确的接管按钮/开关；禁止把自己生成的输入当作人的主动转向。

## PID与调参方法

保留 limited_step 基线，新 fixed_pid 显式启用，默认不替换。P/I/D 单独记录；dt 为相邻有效控制时刻差值（秒）；积分限幅与饱和反积分，微分滤波、初始化防尖峰。死区、人工接管、失效、切换、断连按契约重置；限幅前后量及残差分别记录，处理分数位移积累但不能跨 epoch 遗留。

顺序：P-only→必要时加D→存在可解释稳态偏差才加I。每组冻结场景、种子、人工轨迹、检测结果/模型和延迟配置。误差分段增益属于 gain scheduling，需独立开关、连续切换及消融，不宣称自动学习。没有证据前不实施在线自适应增益。

## 日志产物

每次新目录输出 manifest.json、frames.jsonl、commands.jsonl、transport.jsonl、controller.jsonl、summary.json、report.md，可选 overlay.mp4。manifest 包含 commit、dirty状态/patch摘要、模型/Engine SHA、SDK/GPU、设备/固件、协议、参数、标定版本、启动命令与审计版本。

controller 逐次记录中心误差、P/I/D、dt、预测时域、控制门、进入/退出原因、限幅前后、积分重置、饱和及人工hold/release。frames 记录采集/检测/发布/控制时刻、轨迹、目标点、人工与辅助位移；真值仅用于仿真独立评分。

写日志使用有界队列与轮转。关键命令日志丢失须显式计数并使验收不通过；空间耗尽按已声明策略停辅助或结束试验。不要同步刷盘阻塞每帧控制；记录自身开销及日志是否完整。

## 验收标准

硬门槛零容忍：区外新辅助输出、人工hold期间新辅助命令、错误换人、超出配置位移/速率上限、时钟倒退、执行隐藏真值泄漏、重复执行、命令无终态、伪造ACK/执行、缺失关键日志。任何一项触发不能给总体 PASS。

| 试验 | 必须检查 |
|---|---|
| 左右/上下/四斜向，区内/区外/滞回边界 | 同一算法两轴有效；进入与退出正确；动态中心误差和末段稳定，不只看末帧 |
| 人工大转向、长hold、release、等待中再次hold | 人工输入序列开关完全一致；获知hold后零新辅助；按释放条件恢复；在途残余单独测量 |
| 急停、变向、慢走、遮挡、两人交叉、检测抖动 | 不强行压低协方差，不自动换人；过期/不可靠观测停辅助 |
| 0/20/50/100ms延迟、抖动、乱序、丢包、100%发送失败 | 故障矩阵独立结果；固定/异步成对；停止到达时刻及残余可复算 |
| 半包、ACK碎片/迟到/重复、断开重连、无STOP设备 | 协议失同步可检测，未知不算通过，旧ACK不能授权新epoch恢复 |
| 10分钟正常及10分钟过载；部署版本1小时 | 队列/日志上限不突破，无死锁；至少100次启停；资源趋势及P95/P99报告，存在未终结命令即失败 |

效果门槛在运行前冻结于 acceptance-profile.json：中心误差P50/P95、进入死区耗时、末尾连续稳定窗口、超调、抖动、辅助覆盖率、接管停止P95/P99、残余位移上限。每项须有单位、数值和来源；未设值输出 UNKNOWN，不能跳过。资格由独立评分器重算，不以控制器 assist_state 当分母。左右方向评分用误差方向，不硬编码正增量。

建议首个合成静止目标实验门槛（仅实验、不是用户确认产品标准）：连续末25帧误差≤2.5px，合格需求帧覆盖≥90%，区外/hold违规为0；运动目标、真实设备误差和延迟门槛须经基线与标定冻结，不把静止门槛套给全部场景。开比关有所改善或“仍在48px辅助区域”不等于居中通过。所有正负方向均覆盖，独立新种子重复至少3次。
