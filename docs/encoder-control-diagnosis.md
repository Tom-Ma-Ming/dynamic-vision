# 延迟控制失败分解 · 2026-11-08

代码基线685bd25，未改控制算法或阈值。基于encoder-gain-holdout-v1/runs.jsonl复算，世界横坐标=truth_x+camera_x（仅离线诊断使用，禁止输入控制器）。结果保存在该目录diagnosis.json。

## 边界反向与断轨

simulator.cpp对constant也做世界边界反弹，motion名字不代表整个窗口永不变向。kp2/8-constant-d80-s11都在第147帧改变世界速度方向，第153帧首次不可控，第163帧出现no_selected_track。显式turn的kp2-turn-d80-s11在第100帧变向、第105帧不可控、第115帧no_selected_track。

Selection只在未选择时自动获取；旧selected ID消失后不会自动选择另一个ID。因此不能把后段失控全部归因于PID，也不能简单清空selection去“解决”身份保持问题：多人物场景中这可能切换到错误目标。下一步须追踪关联门控、CV/IMM预测、新旧轨迹及可靠身份恢复，保留目标不可确认时禁发行为。

## 无断轨也有匀速控制偏差

configs/sim-encoder-straight-diagnosis.yml新增独立诊断：速度20px/s、起点160、200帧，没有碰边界；Kp2/8、seed11/29、噪声2px、编码器延迟80ms，其他门槛不变。四项全部FAILED，末40帧始终ready且track_id=1；平均误差依次6.200、6.791、12.628、13.071px。证据artifacts/sim/encoder-straight-diagnosis-v1。该集合用于分解原因，不替代原80px/s动态回归，也不算精度改善。

对于Kp2，原80px/s场景第60～119帧（反向之前）平均真实有符号偏差25.784px，估计位置相对当前真实位置偏差+6.506px。当前只有比例项，输出是速度；维持80px/s需要约40px的控制误差。编码器滞后80ms约对应6.4px，再加默认100ms目标预测约8px，简单稳态估算真实偏差为40-6.4-8=25.6px，与测量接近。20px/s相同估算为10-1.6-2=6.4px，也与新增用例接近。此为稳态近似解释，噪声、量化、瞬态与变向不满足该公式，不能作为所有失败的唯一证明。

修复顺序：先明确最新接收编码器时刻与控制/执行时刻之间的未知位移处理；再评估速度前馈或积分对持续运动误差的影响，避免直接把预测提前量叠加后造成超前；最后单独验收反向/关联/身份恢复。所有估计只能使用已发布检测、已接收编码器/命令反馈，不能用上面的离线真值公式给控制器补偿。
