# 回放日志保留策略

默认配置不变：`log_chunk_bytes=0` 保留完整 `frames.jsonl`，`write_overlay=1` 输出完整视频，适用于离线评分和证据冻结。

`configs/replay-bounded.yml` 为可选容量受限诊断模式：10MiB/段，最多4段，关闭视频。帧日志磁盘总量不超过40MiB；summary.json和其他固定大小输出不计入该额度。只删除本次FrameLog实例创建且纳入内部清单的旧分段；不扫描或清理目录中其他文件。轮转发生在完整记录边界，不拆行；单条记录超出分段预算直接报错，不能静默丢掉内容。

可选键：log_chunk_bytes为0或1024～67108864的整数，log_keep_files为1～100的整数，write_overlay为0/1。开启日志轮转但仍开启视频不能保证整体磁盘有界，因此提供的容量受限配置关闭视频。旧配置无需补键。

摘要新增frame_log：files按时间顺序列出当前分段及记录数；records_written、records_retired分别表示已写入及已淘汰记录数。complete只在无运行错误、没有淘汰且日志记录数匹配processed时为true。它不表示所有输入帧都被处理，latest模式丢帧须另外读取队列计数。配置关闭视频时write_overlay=false。

轮转日志不能直接用于要求完整逐帧证据的评估/小时审计工具。不要拼接残留分段后将其称为完整回放。当前提供的是有界诊断日志，不是断电恢复或跨进程追加方案；启动仍要求新输出目录，已存在文件拒绝覆盖。

本轮5项CPU测试覆盖完整模式、轮转上限/顺序/保留账目、超大/不完整记录拒绝、已有文件保护与配置验证，全部通过。初次测试遇到本机系统TEMP目录拒绝访问，已改用CTest构建目录中专用临时目录，结束只清理由测试创建的目录。原29项CPU测试也通过。

独立目录out/windows-sdk-logcheck的vision_replay已成功编译。运行中的小时测试仍使用原out/windows-sdk程序，不包含本次日志改动；GPU回放集成验证需等小时测试完成后执行，当前未标为通过。
