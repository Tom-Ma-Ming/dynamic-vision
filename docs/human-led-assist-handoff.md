## 用户确认的产品边界

人负责寻找目标和大幅转动镜头。程序仅在已选目标进入画面中心附近的辅助区域时，提供有限的二维微调，使目标保持在中心附近。目标在辅助区域外时，程序不得主动大幅转向、追逐或寻找目标；人主动转向时，辅助应让步。这是当前任务基线，优先于旧文档中可能被理解为全画面自主追踪的描述。

YOLO 训练仍是 head/person 标注监督训练。现有 PID、跟踪及延迟仿真是在验证控制算法，不是在自动训练镜头控制模型，也不是强化学习。仿真仍需模拟微调改变下一帧画面，但人的镜头运动必须作为独立外部输入，不能全部由辅助控制器产生。

## 范围与待定参数

- 仅对明确选中的可靠轨迹辅助；沿用现有选择管理器，不新增“自动选最近人物”。
- 辅助区域以实际控制画面中心为原点，记录画面/ROI 坐标变换；配置进入与退出边界，退出边界不小于进入边界，避免边界抖动。
- 限制单次修正、单位时间速度与加速度；持续误差不能积分成大转向。区域外、失效或人工接管后必须撤销待执行辅助意图并清除累积状态。
- 默认原型采用保守让步：显式人工接管或检测到主动大幅转向时暂停辅助，释放并满足重新进入条件后才能恢复。不得直接用人体运动或背景运动推断为人工输入；若无法取得人工输入，须保留显式接管接口并说明限制。
- 目标丢失、身份歧义、观测过期、当前预测不确定性超限时停止输出；保留轨迹分析不等于继续控制，不自动换人。
- 中心控制参考点须显式配置和记录，沿用经验证的头身关联；本次不自行决定永远对准 head 或 person 的哪个比例。
- 区域大小、死区、位移/速度/加速度上限、人工输入阈值和恢复等待时间尚未由用户确认。先给出有单位、可复现的实验配置及对照，不能宣称实验值已是产品验收标准。无需因此阻塞工程契约和自动测试。

## 执行顺序

1. **先落实有限辅助契约**：增加人工镜头输入、辅助状态机、区域和输出限制，分开记录人工/辅助/实际执行位移。默认禁用新的实验补偿，旧全自主场景保留为诊断，不再作为主产品成功率。
2. **修复仍适用的 P1/P2**：反馈提前读取、预测协方差门控、时钟错位、无条件关闭纵轴、调度时钟倒退和元数据无界。必须在辅助区内验证上下/斜向有效修正。大偏差在新辅助模式下应无辅助输出，而非强行收敛。
3. **建立人主导仿真**：外部脚本驱动人的大转向；目标进入中心区域后才允许有限微调；人的再次转向触发让步。先用合成观测查工程问题，再用渲染→TensorRT→跟踪→辅助命令→新图像验证。
4. **独立评估后再扩展**：比较同一人工输入、目标轨迹、噪声与延迟下的关闭/开启辅助。保留检测、跟踪、镜头运动估计；暂缓合成训练扩展和大范围自主追逐优化。ReID、检测 95% 优化继续按数据和既有后置安排推进。

## 验收重点

| 场景 | 必须可观察的结果 |
|---|---|
| 目标在辅助区外、靠画面边缘 | 辅助命令为零，不因持续误差逐渐接管 |
| 可靠已选目标在区内上下/左右/斜向偏移 | 二维微调有效，所有输出符合配置上限；不得无条件禁用纵轴 |
| 目标进入/退出区域、边界抖动 | 状态转换有滞回；退出后不发新命令，积累项清除 |
| 人主动转向或接管 | 控制器获知后不再产生辅助命令，发出取消；在途不可撤销命令单独记录，按执行器契约统计残余位移及停止延迟 |
| 人释放控制 | 满足等待、选择可靠及区域条件才恢复，不补发暂停期间积累的命令 |
| 遮挡、失效、两人交叉、旧观测 | 停止不可靠辅助，不自动切换人物、不用隐藏真值维持控制 |
| 延迟/丢反馈/乱序 | 控制器只使用已收到信息；使用当前时刻预测协方差；坐标与时钟一致 |

报告分开统计：辅助资格时间、实际辅助时间、区内中心误差 P50/P95、稳定比例、抖动/超调、人工接管后停止延迟和残余位移、越界输出/错误换人次数、退出原因。辅助资格由独立评分器按冻结配置计算，不能通过始终禁用辅助获得“完美”报告。区外正确不动作属于边界通过，不应计为控制失败；同时须保留区内效果未达标的结果。

旧 120px 偏移及动态 24 项保留原始配置、日志与原结论。它们说明旧控制实现的问题，不直接代表新产品主验收。新增区内纵向反例和区外禁动反例，明确标记评估协议版本，不能通过改旧检查器把失败改成通过。反馈因果、时钟和有界状态检查仍是通用硬门槛。
