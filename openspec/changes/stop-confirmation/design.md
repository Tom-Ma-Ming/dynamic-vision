# 延迟停止确认

问题：feedback_transport 的命令回传已延迟，但恢复故障的停止快照此前仍即时返回，恢复时刻与传输假设不一致。

本改动在该开关开启时，对停止快照使用同配置的回传延迟/抖动及丢失窗口。每次请求分配递增 nonce，绑定当前 epoch、请求时刻及独占有效期；最多一个未过期请求和一个待交付回复。过期后重试，替换旧回复；接收检查旧 epoch、旧 nonce、报告时刻和重复消费，且接收时本地执行器/在途命令仍须为空。停机期间不得生成动作。关闭开关保持旧行为。

时间单位为仿真纳秒；报告时刻不早于请求且不晚于接收，接收必须严格早于期限。随机抖动使用独立种子，不能改变命令通道随机序列。有效回复只消费一次；恢复重置 PID、账目并切换 epoch。

范围限制：请求及停止动作仍在本地即时执行，本次只模拟确认的回传；不是带设备停止请求传输延迟的完整双向协议。实际设备必须提供会话/请求对应的停止屏障保证，不能将仿真读取 actuator.idle 当作真实硬件证据。encoder 反馈丢失和异步墙钟调度另行实现。
