# 延迟停止确认

问题：feedback_transport 的命令回传已延迟，但恢复故障的停止快照此前仍即时返回，恢复时刻与传输假设不一致。

本改动在该开关开启时，对停止快照使用同配置的回传延迟/抖动及丢失窗口。每次请求分配递增 nonce，绑定当前 epoch、请求时刻及独占有效期；最多一个未过期请求和一个待交付回复。过期后重试，替换旧回复；接收检查旧 epoch、旧 nonce、报告时刻和重复消费，且接收时本地执行器/在途命令仍须为空。停机期间不得生成动作。关闭开关保持旧行为。

时间单位为仿真纳秒；报告时刻不早于请求且不晚于接收，接收必须严格早于期限。随机抖动使用独立种子，不能改变命令通道随机序列。有效回复只消费一次；恢复重置 PID、账目并切换 epoch。

正向请求扩展：stop_request_delay_ms 默认0，保留本地即时停止模型；大于0时要求feedback_transport，范围不超过10000ms。反馈故障立即禁止新命令并自动发送一次停止请求；停止到达前旧命令可以继续到达/执行，但不能越过自身期限。请求按实际到达纳秒与命令排序，停止在同一时刻优先，推进执行器到该时刻后取消活动命令并清除旧在途命令，等效设备端旧命令屏障。自动停止本身不授权恢复；显式恢复请求也必须经过正向延迟，在设备停止之后才生成确认，再经回传延迟。有效期覆盖整个往返。

最多一个在途停止请求；未送达前不会被新请求覆盖，超时不会让物理停止失效，但旧确认不得恢复控制。断连时到达的停止请求丢弃，既有断连本地急停语义不变。当前正向延迟固定，随机抖动仅用于回传。

范围限制：仅为仿真双向模型；清除旧在途命令模拟设备停止屏障，真实设备必须实现对应epoch/序号拒绝，不能靠控制端清空队列替代。真实设备时钟换算、正向丢包/抖动、encoder反馈丢失和异步墙钟调度另行实现。
