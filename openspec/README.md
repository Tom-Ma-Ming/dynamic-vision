# OpenSpec 变更要求

新任务在 openspec/changes/<任务名>/ 建四份文件，沿用以下格式。已存在的一行摘要为历史实施记录，不能据此判定整阶段完成；逐项证据和缺口以 docs/review-remediation.md 与交接任务表为准。

proposal.md 需写用户目标、问题触发条件、范围、受影响入口与明确的后续工作。

design.md 需写输入输出字段/单位/时钟，状态所有权与线程模型，异常和关闭策略，兼容调用方式，权衡及回退方式。

tasks.md 用带任务 ID 的复选列表，每项对应代码位置、验证命令和证据路径。只有实际运行验收成功才勾选。

acceptance.md 用 Given/When/Then 或表格说明输入、动作、可观察结果、阈值和命令。合成夹具与实景数据分别列出，验收结果不得仅引用文字声明。
